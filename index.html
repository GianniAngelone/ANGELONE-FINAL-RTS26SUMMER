Hardware Security – Tamper Detection System

A FreeRTOS-based ESP32-S3 system that treats a button as a tamper sensor. A fast interrupt signals two bottom-half tasks that measure wake-up latency and log the security event.

Project Overview

This project demonstrates the classic interrupt top-half / bottom-half pattern on FreeRTOS. The button on GPIO 18 acts as a tamper sensor. When pressed, a short ISR records the time and wakes two tasks. Those tasks measure how long it took to wake up and print the result.

The same system can run with or without background load so latency can be compared in idle and loaded conditions.

Platform

ESP32-S3 + FreeRTOS in Wokwi

Interrupt Path

GPIO ISR → semaphore + direct notification

Bottom-Half

Two tasks at priority 12 measure latency

Load Test

Optional App-2 tasks to create contention

System Architecture

         |                 |
    semaphore         notification
         |                 |

+---------------+   +----------------+
| btn_sem task  |   | btn_notif task |

+---------------+   +----------------+

Task Table

Task Priority Role
btn_sem 12 Bottom-half using binary semaphore
btn_notif 12 Bottom-half using direct notification
load_a (optional) 15 Background load – can delay bottom-half
load_b 10 Background load
load_c 5 Background load
load_d 2 Background load

Timing Evidence

Idle (WITH_LOAD = 0)

  • Notification max latency: 30 µs
  • Semaphore max latency: 2309 µs

Loaded (WITH_LOAD = 1)

  • Notification max latency: 17706 µs
  • Semaphore max latency: 10369 µs

Under load the notification path became ~590× slower and the semaphore path became ~4.5× slower. Task A (priority 15) is the main cause of the extra delay.

Hazard Analysis

Delayed Response

A higher-priority load task can delay the bottom-half tasks after the ISR.

Lost Events

A binary semaphore can lose presses if the bottom-half is still busy.

Missing Yield

Without portYIELD_FROM_ISR the bottom-half may not run immediately.
